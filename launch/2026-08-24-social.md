## LinkedIn

Karpathy's `autoresearch` release made a deceptively important point: once the loop is real, small and measurable, Markdown starts becoming organisational code.

An agent edits one file. It runs a fixed five-minute experiment. The result either earns its place or it does not.

That clarity made me look at the operational pieces we have been building around agent work. They fit together rather neatly, so I am open-sourcing five Agent Skills today:

• Agent Orchestra — isolated roles, adversarial review and one integration owner
• Plus Ultra — two independent proposals, one arbiter, apply once, verify fresh
• Cross Agent Sync — source-linked hand-offs across agent harnesses
• Visual QA — deterministic screenshots and independent review for agent-built UIs
• Voice Builder — consent-first, local-corpus editorial support with the human as final author

These are not an autoresearch fork, benchmark or endorsement, and I have not tested them as an integration with it. I see them as optional puzzle pieces around the same deeper idea: autonomy becomes useful when scope, evidence, coordination and authority are explicit.

The Voice Builder release is deliberately not a “clone anyone” system. Real corpora stay local and out of Git. Sources are consented and hashed. Generated text remains a draft until the subject ratifies the exact artefact.

### Body

Karpathy's March `autoresearch` release is compelling partly because the loop is so constrained: the agent edits one training file, runs a fixed five-minute experiment, checks one metric and keeps or discards the change. Its `program.md` is a very small operational contract.

I have open-sourced five Agent Skills that I think are useful *around* that kind of measurable loop:

1. **Agent Orchestra** — defines isolated roles, negative lenses, receipts and one integration owner.
2. **Plus Ultra** — requires two independent proposals, an arbiter, one application pass and a fresh verifier.
3. **Cross Agent Sync** — creates deterministic, source-linked progress hand-offs between harnesses.
4. **Visual QA** — captures a fixed viewport/state matrix and sends it through independent visual review.
5. **Voice Builder** — builds a local conditioning pack from consented, subject-authored sources and keeps publication authority with the human.

This is **not** an autoresearch fork or tested integration, and there is no affiliation or endorsement. The link is conceptual: small instruction files can encode the organisation around a real loop, provided scope and evidence stay explicit.

I took the hardest line on Voice Builder because “voice cloning” is an obvious misuse surface:

- actual corpora/manifests/context packs are ignored by Git;
- every source needs explicit subject authorship and a SHA-256 digest;
- changed bytes fail closed;
- third-party voice evidence is rejected;
- output is marked as draft input until the subject ratifies the exact final artefact;
- the runtime is deterministic and standard-library only.

Reproduce the checks:

```bash
git clone https://github.com/AntreasAntoniou/voice-builder.git
cd voice-builder
python3 -m unittest discover -s tests -v
python3 scripts/validate_package.py
```

The tests use temporary neutral synthetic fixtures only. No real voice corpus is published or required.
